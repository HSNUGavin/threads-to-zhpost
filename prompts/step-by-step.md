# 從零打造 threads-to-zhpost — Prompt 全紀錄

這份文件記錄了我跟 Claude Code 協作的完整過程。每一步都附上我實際下的 prompt 和 AI 做了什麼，讓你看到一個專案是怎麼從一句話長出來的。

---

## Step 1：起手式 — 一句話啟動整個專案

### 我的 Prompt

> 這是空的 repo。需求是：寫爬蟲或用 Chrome MCP 讀這個 Threads 串文，翻譯成中文變成 FB 貼文形式，做成 skill 然後上傳到 GitHub 分享。
> https://www.threads.com/@boris_cherny/post/DWfjnqGFPHE

### AI 做了什麼

1. 先嘗試用 Chrome MCP 讀取 Threads 頁面 — 發現 `get_page_content` 故障
2. 改用 WebFetch — 發現 Threads 是純 JS 渲染，拿不到內容
3. 最後決定用 **Puppeteer** 寫爬蟲，成功抓到 15 條串文
4. 翻譯成繁體中文 FB 貼文格式
5. 建立 `.claude/commands/threads-to-fb.md` skill
6. `npm init` → `git init` → `gh repo create` 一條龍完成

### 學到的

- **不要預設只有一條路**。Chrome MCP 不行就換 WebFetch，再不行就寫 Puppeteer。AI 會自己嘗試不同方案。
- **起手 prompt 不用太細**，給方向和目標就好，讓 AI 自己規劃步驟。

## Step 2：要求做圖 + 文案優化

### 我的 Prompt

> 1. 幫我做一張 FB 宣傳圖片，儘量還原 Threads 原文但翻譯，上面加一個標題
> 2. 文字內容可否再吸引人好閱讀一點、本地化。搜尋其他人都怎樣寫文的去模仿，不是要過度吸引，只是閱讀起來比較順

### AI 做了什麼

1. 派 sub-agent 搜尋台灣科技圈 FB 貼文風格（TechOrange、Inside 等）
2. 用 HTML + CSS 做了一張仿 Threads 風格的深色卡片，列出 15 個功能
3. 用 Puppeteer 截圖產生 PNG
4. 重寫文案：加 emoji 引導、口語化 hook、互動提問

### 學到的

- **「搜尋別人怎麼做」是強大的指令**。AI 會主動研究風格然後模仿。
- 同時要求「做圖 + 改文案」是可以的，AI 會自己拆成平行任務。

## Step 3：圖片設計迭代（6 輪）

這是整個過程中最密集的迭代。圖片設計很難一次到位，需要來回修正。

### 3a — 簡化

> 圖片字太多了，應該要想好重點。例如「Claude Code 創造者自己分享的」，然後可以截圖他的頭像。簡潔、有吸引力，字大一點。

**AI 做了什麼**：砍掉 15 個功能列表，改成大標題 + 頭像 + 副標。用 Puppeteer 從 Threads 頁面爬取了 Boris 的頭像。

### 3b — 強調時效性

> 標語怎麼樣可以強調「剛分享」？

**AI 做了什麼**：把「分享」改成橘色的「剛公開」。

### 3c — 強調數量

> 15 個隱藏功能好像也該強調欸

**AI 做了什麼**：把「剛公開 15 個隱藏功能」整段都變成橘色。

### 3d — 排版檢查

> 排版看一下

**AI 做了什麼**：自己重新檢視圖片，發現整體偏上、底部空白過多、某些文字黏在一起，主動修正。

### 3e — 大小對比版本

> 給我 v2 版本，標題文字大小不同呢？

**AI 做了什麼**：做了一版小字「Claude Code 創造者」+ 大字「剛公開 15 個隱藏功能」的版本，層次感明顯提升。

### 3f — 多版本 + 淺色

> 原本版本可以留著嗎？有 v1、v2。另外再給我一個 Claude 淺底色的版本。

**AI 做了什麼**：保留 v1、v2（dark），新增 v3（Claude 米色底），三版同時產出比較。

### 3g — 定版 + 放大

> 留 v2 dark 和 v3 light，但字都大一點，手機閱讀方便。

**AI 做了什麼**：所有元素統一放大（頭像 100→120、標題 108→128、副標 36→40），刪除 v1。

### 學到的

- **圖片設計一定要迭代**，不可能一次到位。準備花 5-8 輪。
- **短指令效果最好**：「排版看一下」「字大一點」比長篇描述更有效。
- **讓 AI 自己看圖自己改** — 「排版看一下」這種指令會觸發 AI 的自我檢查能力。
- **要求保留版本**是好習慣，讓你有比較和退路。

## Step 4：Skill 化 + 多平台配色

### 我的 Prompt

> 產圖片的部分是否也可以有 skill？然後根據貼文來源生成配色之類

### AI 做了什麼

1. 建了參數化 HTML 模板 `cover-template.html`，用 CSS variables 切換 6 種配色
2. 重寫 `generate-image.js` 支援 `--config` JSON 輸入
3. 建了 `/generate-cover` skill
4. 更新 `/threads-to-fb` skill 整合封面圖產生

### 學到的

- **「是否也可以」是很好的需求探索句型**。不是命令，而是邀請 AI 思考擴展方向。
- 一個好的 follow-up 可以讓工具從「一次性腳本」升級成「可重用系統」。

## Step 5：整理、測試、上線

### 5a — Repo 整理

> 進行完整規劃，幫我清理一下資料夾，變成我可以在 GitHub repo 分享的 skill。

**AI 做了什麼**：刪除舊模板、統一檔案結構、更新 README。

### 5b — 改名

> Repo 我想改名。threads-to..? 中文貼文？

**AI 做了什麼**：提供 4 個選項讓我選，我選了 `threads-to-zhpost`，AI 用 `gh repo rename` 改名並更新所有引用。

### 5c — 標準化 + 測試

> 文檔都更新一下，然後圖片名字應該要標準化，另外跑 sub agent 測試一下產出。

**AI 做了什麼**：
- 檔名統一為 `{作者帳號}-{主題}-{variant}.png`
- 派 sub-agent 跑端到端測試（Threads dark / light / X dark），全部通過

### 5d — 用新 URL 測試

> 測試這個看看 https://www.threads.com/@boris_cherny/post/DWFohOyE1on

**AI 做了什麼**：派 sub-agent 跑完整 pipeline — 爬取 → 分析（辨識出這是新功能發布而非 tips 列表）→ 翻譯 → 產圖。自動調整標題和文案結構。

### 5e — 免責聲明

> 我的 repo 是否要放免責聲明？是否有法律責任？只是實驗性質的專案。

**AI 做了什麼**：分析法律風險點（爬蟲 ToS、著作權、頭像、無關聯性），加上 MIT License + 中英雙語 disclaimer。

### 學到的

- **「跑 sub agent 測試」是殺手級指令**。讓 AI 自己驗證自己的產出。
- **用新資料測試**是最好的驗收方式，會暴露出寫死的假設。
- 法律問題直接問 AI 會給你合理的框架，但重大決策還是要諮詢律師。

## 全流程 Prompt 統計

| 步驟 | Prompt 數 | 核心技巧 |
|------|-----------|---------|
| Step 1：起手 | 1 | 給方向不給細節，讓 AI 自己規劃 |
| Step 2：做圖 + 文案 | 1 | 同時多任務 + 要求參考真實案例 |
| Step 3：圖片迭代 | 7 | 短指令、要求自我檢查、保留版本 |
| Step 4：Skill 化 | 1 | 用「是否也可以」引導擴展 |
| Step 5：收尾 | 5 | Sub-agent 測試、新資料驗證 |
| **合計** | **15** | |

## Prompt 心法

1. **起手要模糊，迭代要精準** — 第一輪給方向，後續輪次給具體修正
2. **讓 AI 自己看自己改** — 「排版看一下」「你有看圖片嗎」比你描述問題更有效
3. **短指令 > 長指令** — 「字大一點」比「請將所有文字放大 20%」更自然
4. **善用 sub-agent** — 測試、搜尋、驗證都可以丟給 sub-agent 平行處理
5. **保留版本** — 設計類的東西一定要留舊版，方便比較和回退
6. **用新資料驗收** — 不要只測開發時用的資料，換一個 URL 跑跑看
